# Rush Hour puzzle library — 441 puzzles in two blocks, each in increasing
# order of difficulty:
#   p01-p49     49 puzzles, one per level from 3 to 51 moves
#   e001-e392  392 puzzles, 9 per level from 4 to 44 moves, then 7, 8, 3, 2
#              and 3 at 45 to 49 moves (every remaining board the filter
#              below leaves at those levels); none at 3, 50 or 51 moves
#
# Format:   <name>: <minimum moves>: <36-character board>
#
# The board is read row-major over the 6x6 grid, one character per cell:
#   o (or .)   empty cell
#   A          the red target car (always horizontal, always on row 2)
#   B, C, ...  the other vehicles (2 or 3 cells, horizontal or vertical)
# The parser also reads a capital O as an empty cell, so no vehicle is labelled O.
#
# The minimum-move count treats one slide of a vehicle, over any distance, as a
# single move. Blank lines and everything after a '#' are ignored. Every line is
# validated at startup, and TestEmbeddedPuzzles re-solves each board by
# breadth-first search to check the count and the ordering within each block.
#
# Source: the boards were selected from Michael Fogleman's exhaustive Rush Hour
# database (https://www.michaelfogleman.com/rush/, 2.5 million puzzles), keeping
# wall-free positions with at least 8 vehicles, then re-scored with the solver in
# internal/rush/solver.go. p02 is the board of the original pygame program.
# The e block keeps 8 to 14 vehicles (a 15th would be labelled O) and no board
# of the p block; it is a seeded random draw (Python random.Random(20261123),
# sorted candidates sampled per level, then sorted by board within a level).
